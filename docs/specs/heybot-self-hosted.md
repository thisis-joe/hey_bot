# Heybot 자체 호스팅과 모델 연결 명세

기준 커밋은 origin/main의 9432ebb다. 설치 단위는 팀 한 곳이며 여러 저장소를 연결할 수 있다. 목표는 새 팀이 Linux에 설치해 선택한 AI 연결로 비공개 시험 PR/MR의 질문·답변·해설을 확인하고 자동 출제를 운영하는 것이다.

## 설치와 역할

- 관리자는 릴리스의 버전 고정 Compose와 이미지로 서비스를 시작한다. 초기화가 DB, 내부 인증, 필수 n8n 워크플로를 준비한다. 재실행은 기존 데이터, 설정, 비밀을 보존한다. 자격 증명과 모델 설정이 없는 새 설치에서 Runner는 실행 상태를 유지하고 모델은 미설정으로 표시한다. Controller와 초기 설정 화면은 이 상태에서도 열린다. 실제 모델 요청은 설정을 성공적으로 활성화할 때까지 미설정 오류를 반환한다. 기존에 명시한 공급자의 구성 오류는 별도로 표시한다. 외부에는 Git 웹훅 경로만 노출한다. 관리 화면과 CLI는 설치 관리자 전용이다. 초기 접근은 루프백 또는 SSH 터널을 사용하고, 브라우저에서 설정을 바꿀 때는 인증된 관리자 세션과 CSRF 방어를 적용한다. n8n·Runner의 내부 토큰에는 관리자 권한을 부여하지 않는다.
- 관리자는 기존 HTTPS 프록시 또는 선택적 Cloudflare Tunnel을 사용할 수 있다. GitHub App 또는 GitLab 봇을 연결한 뒤 저장소 읽기·명령 권한 확인·댓글 쓰기·웹훅을 각각 점검한다. 관리자가 선택한 시험 PR/MR로 질문 미리보기, 명시적 시험 게시, 답변 및 해설을 확인한 뒤 저장소를 활성화한다.
- 기본 동작은 활성 저장소에서 머지 후 기본 질문 두 개를 생성하는 것이다. 저장소 관리자는 수동 출제 및 일시 중지, 언어·제외 경로·선택 기능을 정책으로 정할 수 있다. 머지 전 답변 조건은 저장소가 직접 켠다. 저장소 설정은 설치 관리자의 코드 전송·비용·보관 정책을 완화할 수 없다.
- 기존 질문·채점·해설·명령, 댓글 식별자, 권한, 웹훅 중복 방지와 볼륨·DB 이력을 보존한다. 관리 화면이나 모델 선택을 조작해 기존 댓글의 정답이 변경되지 않는다.

## 모델 선택

| 경로 | 동작 |
|---|---|
| API 키 | OpenAI Responses, Claude Messages, GMS 및 검증된 Responses 호환 게이트웨이. 공급자와 키를 지정하고 계정에 허용된 모델을 고른다. 목록 API가 없는 게이트웨이는 모델 ID를 직접 입력한다. |
| 무료 클라우드 API | 모델 설치 없이 무료 API 키 하나로 시작한다. 관리자가 원하는 독립 공급자를 예비로 추가하고 무료 모델과 우선순위를 정한다. 단일 공급자 후보는 Groq, 두 번째 후보는 OpenRouter의 명시적 무료 모델이다. Gemini 무료 등급은 공개·샘플 코드 시험 후보로 둔다. |
| 무료 로컬 모델 | 모델 계정과 API 키 없이 Ollama를 시작하거나 팀 내부의 기존 엔드포인트를 연결한다. 검증된 추천 모델 또는 설치된 모델을 고른다. 관리자는 첫 다운로드 전 용량을 확인한다. |
| ChatGPT 계정 | 현재 Codex CLI 로그인을 기존 설치에서 계속 사용할 수 있다. 새 관리 화면의 공식 계정 연결은 모델 조회, 갱신·해제, 사용량 귀속 및 계정 소유자·팀원·무인 머지 범위를 확인한 뒤 노출한다. Heybot에서 연결을 해제하면 이후 로컬 호출과 갱신을 멈추고 저장된 자격 증명을 제거한다. 공급자의 계정·호스트별 귀속 및 권한 회수는 제공자가 실제 지원하는 범위를 구분해 표시한다. Claude의 첫 배포 경로는 API 키다. Claude 구독을 팀 서버 옵션으로 제공하려면 해당 사용 방식에 대한 공급자 지원 근거가 필요하다. |

초기 설치 안내는 서버 모델 설치를 피하려는 팀에 무료 API 체험을, 모델 계정과 키가 없는 팀에 무료 로컬 모델을 보여준다. 모델 연결은 공급자·선택 모델·과금 방식·대상 주소·저장소 적용 범위를 표시한다. 저장 전에는 공개 고정 샘플로 인증, 읽기 도구 또는 승인된 자료 수집 경로, 구조화 출력을 확인한다. 샘플 검사는 관리자가 요청하고 실제 비공개 코드 시험은 대상 PR/MR을 고른 뒤 명시적으로 실행한다. 성공한 설정만 원자적으로 활성화한다.

관리자는 모델별 능력을 실측한 결과로 지원 목록을 정한다. 구조화 결과는 전송 경로와 무관하게 기존 스키마·코드 위치·정답키 확인을 거친다. 모델별 최초 질문 이중 풀이 여부는 명시적인 기능 설정으로 표현하고, 기존 Luna 설정은 호환 기본값을 보존한다. 기존 GMS·Codex·Claude 설정은 관리자 저장이 있기 전까지 그대로 적용한다.

## 무료 한도와 재시도

1. 무료 체험 정책에는 관리자가 승인한 무료 모델·실제 전송 대상·저장소 범위만 기록한다. 중계 서비스의 실제 추론 공급자도 확인한다. 유료 요청, 승인 범위 밖의 코드 전송, 같은 공급자의 계정·조직·프로젝트·키 순환을 자동 전환 대상에서 제외한다. 무료 여부 또는 실제 전송 대상을 확인할 수 없는 경로 역시 자동으로 호출하지 않는다. 공개 전용 모델은 샘플 또는 관리자가 승인하고 플랫폼에서 공개 상태를 확인한 저장소에만 쓴다.
2. 공급자가 밝힌 짧은 재시도 시간은 우선 따른다. 초기 정책은 30초 이내이며, 대기는 실행 소유권을 내려놓고 DB에 기록한다. 더 긴 대기 또는 확인된 한도 소진은 해당 공급자를 대기 상태로 두고, 같은 실행 예산 안에서 다음 승인 연결을 한 번씩 시도한다. 한도 응답에 시간이 없으면 기본 15분 뒤 다시 확인하고 UI에는 재시도 예약 시각으로 표시한다. 계정 인증, 구성, 모델 출력 오류는 한도 소진과 구분한다.
3. Runner는 한도 분류와 공급자가 제공한 재시도 정보를 반환한다. Controller는 임대 소유권 확인과 함께 같은 DB 작업의 다음 실행 시각, 연결 설정 버전, 시도한 연결 및 예산, 공급자 대기 상태를 보존한다. n8n은 예약 시각 이후 해당 작업을 다시 선점하도록 요청한다. 후보가 전부 제한되면 같은 논리 작업이 대기하고 실제 생성 실패 횟수를 소비하지 않는다. PR/MR당 예약 대기 상한은 최초 한도 소진 시각부터 24시간이다. 같은 대기 구간에서 반복 호출하는 일을 막고, 상한에 이르면 자동 재등록을 종료하고 관리자와 사용자가 원인을 확인한 뒤 수동 재요청할 수 있게 한다.
4. 하나의 생성 시도는 해당 시도의 모델에 고정한다. 검증·수정을 포함한 최초 질문 생성 중 한도로 전환할 경우 같은 소스 스냅샷으로 시도 전체를 새로 시작한다. 이전 공급자의 부분 출력과 대화 이력은 옮기지 않는다. 대기·전환 중에도 작업 시간 예산과 PR/MR당 시도·호출 상한을 적용한다. 이전 소유자가 결과를 뒤늦게 기록할 수 없도록 기존 lease와 검사를 사용한다.
5. 이미 질문 결과를 DB에 기록한 작업은 그 결과로 게시를 재시도한다. 응답 유실 뒤 실제 게시물을 현재 마커로 대조하여 중복 댓글을 막는다. 관리자 UI에는 마지막 공급자, 한도·전환 사유, 다음 재시도 시각과 연결 상태를 표시한다.

새로 시작한 작업은 그때의 기본 설정을 읽는다. 이미 시작한 작업은 설정 버전과 시도 후보를 보존한다. 매 외부 호출 직전에 최신 연결 권한·저장소 전송 승인·실제 추론 대상·키 유효성·무료 정책을 확인한다. 중계기는 확인한 공급자로 제한하고 승인 범위 밖 자동 전환을 막는다. 예비 후보를 새로 허용한 설정은 다음 작업 또는 관리자의 명시적 재요청부터 적용한다. 취소·키 해제는 후속 호출부터 효력을 가진다. 비밀 원문과 코드·프롬프트는 일반 로그, 작업 상태 API, n8n 실행 이력에 넣지 않는다.

## 운영과 공개 기준

- 현재 Git 캐시, 코드 스냅샷, 질문·답변의 보관 수명을 구분한다. 설정·비밀·DB·n8n 상태를 백업하고 복구한 후 모델 연결과 기존 댓글 해설을 확인한다. 업데이트는 매칭되는 Controller·Runner·워크플로를 한 단위로 다루며 손실 없는 마이그레이션과 이전 릴리스 복원을 시험한다.
- 첫 설치 파일럿은 무료 로컬·Claude·OpenAI/GMS를 확인한다. 모델이 없는 서버를 위한 무료 API 체험 공개 범위에는 최소 한 곳의 실제 무료 호출 검증이 필요하다. 무료 자동 전환은 독립 공급자 두 곳에서 확인한 뒤 제공한다. 특정 구독 계정, 미검증 모델, 사내 Git 버전은 검증된 범위에 맞춰 안내한다.
- 공개판은 신규 Linux 설치·이전 운영 데이터 업그레이드, GitHub·GitLab, 주요 머지 방식과 이전 댓글, 한국어·영어를 증거로 확인한다. 로컬 후보는 합의한 공개 평가 PR에서 정답의 유일성·코드 근거·스키마·생성시간·메모리를 측정하고 그 결과로 추천 모델과 지원 사양을 확정한다. 설치 경로와 API 시험은 운영 키·운영 저장소를 사용하기 전에 fixture와 승인된 샘플로 검증한다.

실행 순서와 검증 항목은 [구현 계획](../plans/heybot-self-hosted.md)에 둔다.
